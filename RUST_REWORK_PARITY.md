# Rust Rework — матрица функционального паритета и честный прогресс

**Цель:** заменить текущую Electron/Node.js версию `main` на Rust + Tauri без потери пользовательских сценариев. Это **не** разработка новой «v2».

**Правило приоритета с 2026-11-22:** `main` — функциональный эталон. Сначала перенос существующих кнопок, экранов, редакторов, навигации и пользовательских сценариев; новые функции и дополнительная семантика RobustToolbox — **после** миграции. Новые технические механизмы без паритетного сценария не повышают оценку.

**Подтверждённый разрыв по исходникам:** старый `Inspector.tsx` содержит *Linked prototypes*, а старый `SettingsModal.tsx` — конфигурацию requiredLocales и отдельные Updates/About. В новой ветке функционал ссылок теперь перенесён в `LinkedPrototypePanel.tsx`; Settings/локали/обновления ещё требуют переноса. В старом `Editor.tsx` есть действия по исправлению отсутствующей локализации, для которых Tauri пока не воспроизводит тот же полный сценарий. Это задачи паритета, а не пожелания о новых возможностях.


## Почему старые 40 → 41 → 42 → … → 46% некорректны

Предыдущие проценты увеличивались примерно на один пункт за рабочий цикл. Это **не** был подсчёт перенесённых функций и не отражало их трудоёмкость. Исторические отметки сохранены в основном плане как журнал, но **не являются метрикой готовности**.

Ни число коммитов, ни успешно пройденный CI, ни количество строк кода не доказывают функциональный паритет. В частности, полноценное создание/редактирование RSI, межплатформенная установка и корректная семантика C#/YAML занимают больше работы, чем несколько отдельных форм редактора.

## Новая шкала

У каждого направления есть **вес** (доля функциональной цели) и **стадия зрелости**:

- **0/4:** нет работающего переноса;
- **1/4:** есть отдельный рабочий путь, но большая часть сценариев отсутствует;
- **2/4:** есть полезная реализация и автоматические тесты, однако много ограничений;
- **3/4:** большинство типовых сценариев реализовано, остаются существенные пробелы;
- **4/4:** проверен функциональный паритет с `main`, безопасность, регрессии и пользовательский сценарий.

`Оценка = Σ(вес × стадия / 4)`. Веса — **инженерные допущения**, а не измеренная трудоёмкость. Стадия **4/4 не может быть присвоена до финального user-теста**.

Из-за широких ступеней процент меняется **только при закрытии существенного набора критериев**, а не после каждого цикла.

**Новый сквозной сценарий (entity → Fluent, текущий цикл):** выбор конкретного обычного YAML-entity, инспекция прямых полей в Rust, предпросмотр новых Fluent-значений в выбранном существующем FTL и конфликтозащищённая запись. Отсутствующие файлы, наследование и автоматический обзор всех языков не покрыты. Баллы до успешной проверки CI и GUI не увеличиваются.

**Наблюдаемость открытия проекта (новый R06/R07 цикл):** Rust сообщает реальные этапы сканирования и накопленное число ресурсов; React показывает их во время открытия. Проценты намеренно не выдумываются. Это не отменяет полного сканирования и не закрывает требования к производительности или пользовательскому тесту.

**R05 — множественные parent-связи (новый цикл):** добавлены отдельный UI-редактор упорядоченного списка прямых родителей и Rust patch/inspect без общей YAML-сериализации. Поддержаны простые одиночные значения и списки, проверки identity/siblings/comments и тесты. Это **не** реализация runtime-наследования RobustToolbox, merge PartialPrototypes или редактирования любого сложного YAML. Вес и стадия R05 пока не меняются.

**R06 — частичное обновление индекса (2026-11-22):** watcher сохраняет все пути в пачке, Rust обновляет затронутые файлы и подкаталоги YAML/FTL/RSI, C# изменения сбрасывают ленивые кэши. Сохраняются immutable snapshot, безопасная публикация и защита черновиков. Неизвестные пути, переполнение и ручное обновление вызывают полный рескан. Новые Rust-тесты сравнивают результаты с полным индексом. До GUI-smoke, замеров на большом реальном форке и дискового кэша стадия R06 остаётся 2/4.

**R07 — живой YAML-инспектор (цикл 2026-11-22):** возрождён сценарий выбора прототипа **из самого открытого файла**, по актуальному несохранённому тексту. Текущие декларации, родители/abstract, tagged partial и CreateVariants отображаются по структуре YAML; переход к Monaco, существующие формы редактирования и прямой Sprite.sprite → RSI + Sprite.state соединены в одном интерфейсе. Важные ограничения: нет resolved inheritance/merge semantics RobustToolbox, композитного Layer/image preview, переходов по всем ссылкам, GUI smoke. Поэтому вес и стадия R07 **не меняются**.

**R07 — исходные Sprite.layers и живой RSI-предпросмотр (2026-11-22):** инспектор показывает Sprite.sprite/state и до 32 явных Sprite.layers с visible, shader и независимым/общим RSI-путём. Можно выбрать каждый слой и просмотреть его анимацию/направления на основании настоящего PNG и meta.json (через безопасный Rust reader). Проверяются наличие индекса, состояние в метаданных и соответствие кадров сетке. Не выполняются игровые shader, смещения, наследование и объединение слоёв; это **не** итоговый runtime-спрайт. GUI-smoke пока нет, поэтому 53/100 сохраняются.

**R05 — транзитивное наследование как граф источников + происхождение полей (2026-11-22):** расширена прежняя инспекция прямых parent-ссылок: полный ограниченный BFS по обычным исходным объявлениям, с точными file/line, пометками о partial, tagged, ambiguous, missing и циклах. Новый ленивый просмотр читает исходники каждого предка и показывает объявленные YAML-ключи и типы компонентов, сохраняя порядок/происхождение partial-деклараций отдельно. Поиск идёт по сохранённому индексу (не по несохранённым черновикам). Это **не** семантически разрешённый RobustToolbox: наследование DataField, !Remove/!Clear/!Add и порядок операций с partial ещё требуют отдельного механизма и тестов на реальном форке. Стадия R05 остаётся 2/4, оценка проекта — 53/100.

**R05 — ограниченный вычислитель PartialPrototypes (2026-11-22):** после source ancestry/provenance добавлен отдельный tag-aware preview базового объявления и partial-правок. По подтверждённым правилам Space Wizards обрабатывает mappings, sequences, !Clear, !Remove, !Index:N, !CombineIndex:N, scalar/list parent и entity.components как словарь по type; отдельный UI показывает результат и provenance последнего изменения. Обязательные ограничения: нет применения inheritance от родителей к computed YAML, DataField/C#-семантики, гарантий по неизвестным тегам и порядку одинаковых partial index. Все операции read-only; обнаруженная неоднозначность отражается в статусе exact=false. Это не полный SS14 runtime resolver; оценка R05 **сохраняется 2/4**, общий балл **53/100**. Референс: https://docs.spacestation14.com/en/robust-toolbox/partial-prototypes.html

**R05 — структурное наследование через цепочку parent + partial (2026-11-22):** добавлен ограниченный рекурсивный Rust-резолвер по сохранённым YAML-источникам, применяющий сначала partial-правки каждого предка, затем его статические поля и entity.components. Обычные списки при наследовании заменяются дочерними (в отличие от partial-append), компоненты совмещаются по type, вложенные словари сохраняют неотменённые ключи. Есть кэш для повторных предков, лимиты глубины/объёма, диагностика циклов/пропавших файлов/неоднозначного множественного наследования, отдельная кнопка в UI и тесты. Источники с неподтверждённой семантикой отмечаются неполными. Структурная целостность не равна точности runtime: C# DataField, AlwaysPushInheritance/NeverPushInheritance и custom serializers пока не разрешаются; полная работа со сложным YAML отсутствует. Поэтому стадия R05 **пока 2/4**, общая оценка **53/100**.

## Как теперь обновлять прогресс

1. Каждый рабочий цикл добавляет код, тесты и проверяемые ссылки на CI — **без автоматической прибавки процента**.
2. При закрытии крупных сценариев обновляются стадия, обоснование и таблица; сравнение ведётся с текущей `main`.
3. Любое увеличение стадии должно иметь измеримый критерий и тесты. Можно **понизить** оценку, если найден существенный недостающий сценарий.
4. Сборка в CI не подтверждает качество интерфейса. Ручной user-тест остаётся **на финальный этап**, как согласовано.
5. «100%» требует паритета пользовательских сценариев, отсутствия критических потерь/гонок и испытания устанавливаемых сборок; количество строк Rust роли не играет.

Этот документ — **методика и предварительный аудит**, не гарантия сроков, релизной готовности или числа оставшихся часов работы.

**R07 — перенос настроек из Electron (2026-11-22):** Tauri-диалог имеет разделы General, Editor, About; версия получена через Tauri API. Отдельная настройка игровых `requiredLocales` хранится в прежнем ключе `ss14-studio-localization-settings`, не связана с языком интерфейса, и служит для выбора локальных FTL-файлов редактором. Есть регрессионные тесты хранения и разделения UI/game locale. Всё ещё **не перенесены** автоматическая диагностика missingLocale для всех требуемых локалей, quick-fix создания локалей, аппаратное ускорение, updater и ручная GUI-проверка. Общую оценку не повышаем.

**R07 — диагностика локализаций entity (2026-11-22):** нативный read-only analyzer на существующем кэшируемом Fluent-индексе проверяет прямые поля entity во всех настроенных игровых локалях, различает недостающие `name/desc/suffix`, выводит пути FTL, ограничивает неполные сканы и дубликаты, предоставляет переход к уже существующей безопасной форме дополнения FTL. Это перенос сценария Electron `analyzePrototypeLocalization`, не новый функционал. **Не готово:** автоматическое создание отсутствующего FTL, массовая запись по нескольким локалям, inline-маркеры Monaco, ручной GUI smoke.

**R07 — missing FTL quick-fix (2026-11-22):** карточка отсутствующего перевода запускает уже существующий мастер создания FTL с указанными `file`, `localizationId` и `name`. Запись по-прежнему проходит через нативный `create_new_fluent`, не перезаписывает существующий файл и требует существующего каталога локали; другие поля потом можно дополнить из редактора. Язык UI и языки игровых ресурсов остаются независимыми. Не заявляется автоматическая запись всех полей и локалей.

**R07 — восстановление полного первичного блока FTL при quick-fix (2026-11-22):** старый `createPrototypeLocalization` умел переносить `name`, `description`, `suffix`. Теперь quick-fix нового FTL передаёт все три явно заданных значения в существующий native create path (отказ от перезаписи, проверки однострочности, лимиты, create_new, sync). Диалог показывает исходные .desc/.suffix только при создании FTL для entity. Это перенос, не дополнительная функциональность.

**R07 — внешнее создание FTL из Electron (2026-11-22):** восстановлен выбор destination=project/external. Внешний путь выбирается только в native Rust save dialog, не передаётся JavaScript; новая запись всегда через create_new, с проверкой расширения и синхронизацией. Внешний файл не добавляется в индекс открытого проекта, как и в старом отдельном сценарии. Новые файлы не перезаписывают существующие.

**R07 — внешнее создание RSI (2026-11-22):** возвращён режим из Electron `destination=external`: пользователь выбирает каталог системным диалогом через Rust, формируется `name.rsi/meta.json` с проверками из уже существующего native preview. Создание каталога эксклюзивное; при ошибках meta.json операция откатывается. Внешний RSI не добавляется в индекс проекта.

**R07 — внешнее создание YAML-прототипов (2026-11-22):** в мастере создания восстановлен Electron-путь destination=external для нового файла. Native Rust сохраняет YAML, прошедший существующий preview/validate, в выбранный пользователем системным диалогом путь; проверяет расширение, использует create_new и не добавляет внешний файл в открытый индекс. Режим append остаётся строго внутри открытого проекта, с контролем ревизии.

**R07 — живые предупреждения об отсутствующих игровых переводах в инспекторе YAML (2026-11-22):** выбранный обычный entity по содержимому несохранённого YAML асинхронно проверяется на требуемые FTL-локали с задержкой из настроек редактора.
