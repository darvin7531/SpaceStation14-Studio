# SS14 Studio — Rust Rework

**Branch:** rework/rust-tauri  
**Current preview:** 0.1.5-alpha.1 (pre-1.0, not v2).

SS14 Studio is being rewritten on **Rust + Tauri 2**. The desktop application in this branch has no Electron and no Node.js desktop runtime. Node.js is used only during frontend development/build through React, TypeScript and Vite. The old Electron implementation remains on the main branch for reference during feature migration.

## What is working now

- A native Tauri window with a lightweight React interface and an OS-native folder picker (only `dialog:allow-open` permission). The last successful project path is remembered locally.
- Open and verify the root directory of a Space Station 14 source checkout.
- Read-only inventory of YAML prototype files, RSI folders and Fluent files.
- **Lazy Rust YAML declaration catalog:** enumerate real prototype `type` + `id` entries, parents, abstract flag, source line and multi-document origin. Search uses a prebuilt in-memory index; parse happens once when the Prototypes pane is opened.
- Partial declarations are kept separate: configured partial directories from `Resources/PartialPrototypes/partialPrototypes.yml`, `!PartialOnly`, `!Partial:0`. Unsupported dynamic IDs are reported, not silently treated as ordinary prototypes.
- Source-level prototype graph: direct parent links, reverse child references, definition provenance, conservative missing-reference and static cycle diagnostics. Links from partials stay tagged by provenance; dynamic references are never assumed to be a confirmed engine inheritance path.
- Parsed YAML diagnostics are exposed in a separate paginated view. A malformed source file is reported without poisoning the index of other files.
- Search by resource path and type, with pagination; queries use precomputed case-insensitive keys and resource reads use a direct lookup map, with no filesystem walk per search.
- Display and edit YAML/FTL contents in a Monaco-based syntax-highlighted editor, with RSI meta.json in a separate sprite-sheet inspector. Monaco and its worker are bundled locally (offline); JSON metadata uses lightweight syntax colouring without the heavy JSON language service. Open tabs are bounded and support close/reload.
- Actionable Russian-language error handling with stable codes, hints and expandable technical details.
- Frontend YAML/FTL draft buffers with explicit discard confirmation on tab close, reload and project switch; Ctrl+S saves the active YAML or Fluent file. Per-project recovery snapshots are now written to the Tauri app-data directory (not the SS14 checkout), using SHA-256 keys, bounded text, restricted permissions on Unix, same-directory temp file and atomic replacement. UI compares the stored text to the current disk version, and requires deliberate conflict resolution before an outdated recovered draft can overwrite external edits.
- Conflict-aware raw YAML text-saving backend (not semantic editing): SHA-256 revision checks, syntax validation, same-directory temporary file + fsync + replace, symlink refusal, cache invalidation, and no implicit overwrite. Edits are byte-preserving with respect to the user's submitted text (comments, order and SS14 tags are not reserialized). RSI metadata is read-only in the general text editor; a dedicated append-only importer can add new states and PNGs with revision protection. Fluent uses the same revision-checked save flow and has separate syntax diagnostics.
- **Create prototype (new-file and append modes):** Rust-validated wizard for type, ID, one parent, abstract/name/description, entity Sprite/Item/Physics/Appearance stubs, destination path and authoritative YAML preview. New files use exclusive `create_new`. Appending is limited to *already indexed* conventional one-document YAML sequences, never Partial-tagged or multi-document files. Rust parses the original, constructs one new sequence item without reserializing existing source, validates the combined YAML and its list length/content, and verifies an exact SHA-256 expected revision before atomically saving. Duplicate type+ID declarations are rejected; the frontend blocks appending into an open dirty tab. After writing, the prototype catalog refreshes while unrelated drafts stay intact. Full structural/CST block editing is still future work.
- **RSI animation viewer:** validates version-1 metadata, frame dimensions, directions (1/4/8) and per-direction delays, then crops source PNG sheets into individual frames without changing their bytes. Supports frame navigation, speed-aware playback, direction selection, zoom and raw PNG fallback. Rust validates PNG IHDR and rejects dimension/decompression bombs before sending image data to the WebView. Invalid metadata is reported with actionable warnings.
- **Exclusive new RSI creation:** the Rust wizard creates a new `Resources/Textures/**/*.rsi` directory and `meta.json` after checking the path, parent symlinks, size/license and collisions; existing files are never overwritten. It starts with no frames, refreshes the project index and opens the new RSI. Importing a **new** state from PNG is supported; replacing an existing state or editing/removing frames is future work.
- **Append-only RSI PNG import:** select a local PNG in the RSI viewer, set a new state name, direction count (1/4/8), frame count and delay; Rust checks data URL size, structural PNG chunks/CRC, decoded dimensions, exact frame grid and unchanged SHA-256 meta.json revision. It exclusively creates `state.png`, stages a new meta.json and commits it by rename. Existing PNGs/states are never overwritten. The preview cache receives the new revision. This is a two-file operation, **not** a crash-atomic filesystem transaction: a sudden power loss before metadata replacement can leave an unreferenced new PNG. Existing states remain intact; users may remove orphaned files manually after verifying them.
- **Existing RSI timing editor:** the viewer offers per-frame, per-direction delay editing for existing RSI v1 states. Rust checks the current SHA-256 revision, requires exactly the original number of frames/directions, preserves unknown JSON properties, and saves only `meta.json` through a same-directory, revision-checked temporary-file replacement. PNG bytes and state order are not modified. JSON formatting/key order may be normalized. Changing the number of frames, replacing/deleting PNGs, and fully transactional multi-file recovery remain future work.
- **Archive-backed RSI state removal:** RSI viewer provides an explicit name-confirmation flow to remove an existing state. Rust requires the current metadata SHA-256 revision, archives the original PNG and pre-edit `meta.json` with a manifest under that RSI's hidden `.ss14-studio-archive/` directory, fsyncs the archive, then saves the new metadata through the revision-checked atomic writer. It deletes the original PNG only when its contents still match the archived snapshot; otherwise it leaves it on disk with a warning. The backup stays available for restoration. An explicit **Restore archived state** panel now lists bounded, verified-manifest archive candidates and can restore exactly one state and PNG after checking current meta.json SHA-256, archived file checksums, compatible version/frame size, and absence of existing PNG/state. It preserves unrelated changes made since deletion and never overwrites a current file. A crash between writing the new PNG and publishing metadata can still leave an orphan PNG, and automatic cleanup/recovery across process crashes is not yet supported. Neither deletion nor restoration is a crash-atomic multi-file transaction.
- **Existing prototype field form (conservative first slice):** use the “Поля” action on an ordinary indexed declaration to edit simple `parent`, `name`, `description` and `abstract` fields. Rust verifies document/item identity and original vs resulting YAML AST, changes only specific source lines without serializing the entire document, and refuses ambiguous/complex layouts or Partial declarations. The patch changes the in-memory editor draft only; use the existing Ctrl+S with SHA-256 conflict handling to persist it. List-valued parents, tagged fields and block scalar descriptions remain text-editor-only.
- **Create/remove scalar component fields:** the components pane now supports typed new direct fields and removal of existing direct scalar fields with confirmation. Rust checks component index and type, prevents duplicate keys and type confusion, refuses deleting comments or special YAML structures, and verifies the resulting YAML tree so other components/fields cannot change. All edits go to the in-memory draft; disk persistence still requires the existing Ctrl+S revision-protected save. C# DataField validation is not yet available.
- **Component scalar field editing:** the components panel now lists direct field names, inferred YAML scalar kinds (`string`, `bool`, `int`, `float`) and nested/complex fields as read-only. A typed field edit rewrites only its direct source line, preserves inline comments and line endings, and validates that the YAML tree changed only at that exact field of the exact component; stale component identity, duplicate or unusual source fields, tags, multi-line strings, and invalid numbers are rejected. The result remains a draft until Ctrl+S, with no automatic disk writes. Fields are not yet validated against C# `DataField` metadata.
- **Prototype components (conservative first slice):** for ordinary `entity` declarations, the “Компоненты” action shows explicitly declared components and their field counts; you can add a minimal `type` component block or remove a selected block after confirmation. Rust checks the exact source item identity, validates the resulting YAML tree, and rejects cases where other declarations/fields change. Existing source text is not globally serialized; deletion refuses comment-bearing blocks. All operations apply only to a draft; Ctrl+S performs the conflict-aware disk write. This is not an inheritance-aware component inspector or a full nested-field editor. Complex/partial/tagged layouts are intentionally unsupported.
- **Cached Fluent locale index:** the active FTL editor now checks duplicate message/term IDs, missing message/term references, missing attributes and references to attribute-only messages within the same locale. The index is built lazily from indexed FTL files, bounded (4096 files / 64 MiB), invalidated after FTL saves and reset on workspace refresh; the live unsaved file overlays its on-disk version. Files that cannot be read or parsed cause a clearly marked *incomplete* report, suppressing missing-reference claims. Runtime locale fallbacks and file layering are not modeled.
- **Live Fluent syntax diagnostics:** the bundled official `fluent-syntax` parser analyzes the active in-memory FTL draft on a 300 ms debounce off the UI thread; a pane reports up to 100 syntax errors with line/column and a click-to-jump action. It handles recovery after malformed entries and maps UTF-8 byte positions to visible character columns. Parsing does not rewrite files, block saving, or claim validation of resource references, duplicate keys across files, or SS14-specific extensions. Per-file parsing is bounded to 4 MiB.
- **Fluent text editing and new-file creation:** indexed `Resources/Locale/**/*.ftl` files support Monaco edits, Ctrl+S, conflict diff, revision-checked atomic save, and the same recovery journal as YAML. A dedicated Fluent wizard previews one simple starter entry and creates new FTL files only in **existing** locale directories using exclusive `create_new`; any existing target is refused. New files are indexed and opened immediately when the rescan succeeds. Text is never normalized. Formal Fluent syntax validation, automatic creation of locale directories and prototype-to-localization cross-references remain future work.
- **Explicit safe index refresh:** a Rust-side full rescan builds a new immutable project snapshot before atomically swapping it. Before scanning, the UI flushes current dirty YAML buffers into the recovery journal; failure or a durability warning aborts refresh. It then keeps open tabs and unsaved YAML drafts, reloads changed clean tabs, and warns about dirty tabs whose disk revisions changed or whose files disappeared. No automatic acceptance of external changes or disk writes occur during refresh. The full rescan is a stepping stone toward incremental filesystem watching.
- **RSI PNG-sheet preview:** index only real PNGs inside the chosen RSI, load one selected PNG on demand over a bounded (8 MiB) Rust IPC call, reject symlink/path traversal and invalid PNG signatures, and show pixelated zoom and meta.json states. This is a **sheet viewer**, not yet a frame slicer or animation player.
- **YAML diff review:** a locally bundled, lazy-loaded Monaco diff editor compares the current disk version with an unsaved or restored draft, highlights edits, and lets the user toggle inline / side-by-side views and whitespace comparison. The preview is read-only, with a text fallback for very large files or editor initialization errors. Conflict review must be manually accepted and rechecks disk revision and the exact reviewed draft; accepting a revision never saves source text on its own.
- Recovery is best-effort: snapshots are debounced by 750 ms, so the last keystrokes immediately before a crash might be absent. A failed journal write is surfaced as an error; no unconditional promise of backup durability is made.
- Rust/TypeScript CI checks and unit tests.

**Limitations:** Diff is a review/decision tool, not automatic three-way merging; manually reconcile conflicting YAML before saving. Current counts refer to YAML *files*, not individual prototype declarations. This is an early functional Rust preview, not a feature-complete replacement for the old editor. Existing-prototype visual/YAML-CST editing, resolved inheritance, C# symbol extraction, persistent incremental index and animated/individual-frame RSI preview are intentionally not claimed as implemented. The prototype catalog is a read-only *declaration index*, not an engine-accurate resolved graph. External file additions/deletions can be discovered with **Обновить индекс**; this is currently a manual full rescan, not a background watcher or persistent incremental index. Dirty drafts for deleted sources stay in memory, but journal persistence of deleted/unindexed files is not guaranteed; copy their contents elsewhere before closing. File writes are protected by application-local serialization and optimistic revision checks, not by an OS-wide lock; a concurrent external writer can theoretically race between the final check and rename.

## Develop

Install Node 22+, the stable Rust toolchain and Tauri 2 system prerequisites:

- https://v2.tauri.app/start/prerequisites/

Run from the repository root:

    npm install
    npm test
    npm run build:web
    cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
    cargo test --manifest-path src-tauri/Cargo.toml --all-targets
    cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
    npm run dev

CI also compiles the complete Tauri application with `npm run build -- --no-bundle` (Linux). It does not launch the GUI or generate an installer. Production packaging is not enabled until editing, feature-parity and platform-smoke tests are added. The root package uses npm semver dependencies; a lockfile and pinned release build are mandatory before a binary release.

## Architecture

- UI: React + TypeScript + Vite. Never touch project files directly.
- IPC boundary: src/lib/api.ts — only typed, narrow Tauri commands.
- Backend: src-tauri/src/lib.rs and src-tauri/src/project.rs.
- Errors: src-tauri/src/error.rs and src/lib/errors.ts.
- Project index: immutable snapshot loaded off the UI thread and atomically replaced; searches never traverse the filesystem.
- Source files are authoritative. Derived indexes must be rebuildable.

## Native C# schema index (experimental)

The Rust Rework can lazily scan C# source files through **Tree-sitter C#** (without Electron's regex scanning windows). Use **C# схемы** after opening a project to browse `[RegisterComponent]` components, `[Prototype]`/`[PrototypeRecord]` kinds, and immediate `[DataField]` fields/properties with C# types and source locations. The scan skips generated build directories, `Resources` and symlinks, and limits work to 20,000 files, 2 MiB per file and 128 MiB total. Results are cached per project and reset on index refresh. The UI reports skipped files and uncertain C# parses.

The YAML component inspector also requests C# metadata for its explicitly listed components. It shows the direct class source and its DataFields, offering a *prefill-only* button for safe primitive fields not present in the YAML draft. The button fills the existing add-field form; nothing is written until the user applies the YAML change and saves. Ambiguous, partial, uncertain or incomplete C# schemas cannot auto-suggest fields. Names absent from the index are not treated as invalid components.

Related `partial` C# declarations carrying `DataField` are now grouped by their **fully qualified namespace and type**, including unannotated companion files, and presented with their own file/line provenance. This is a conservative *candidate group*, not compiler-level merging: the YAML inspector still disables automatic field suggestions for `partial` classes. Identically named classes from unrelated namespaces are not grouped; identical names across separately compiled assemblies are not distinguishable without project/assembly analysis.

This is **structural C# metadata**, not compiler semantic resolution: inherited fields, preprocessor symbols, multiple partial declarations and generated code need further handling. No source files are changed by the C# indexer.

## Rework roadmap

For the continuously updated task-level checklist and development cycles, see [RUST_REWORK_PLAN.md](RUST_REWORK_PLAN.md). For a weighted, explicitly uncertain assessment of Electron parity and a breakdown of missing user scenarios, see [RUST_REWORK_PARITY.md](RUST_REWORK_PARITY.md). The old practice of adding one percentage point per commit has been retired.

1. Complete unported settings, workspace UX and i18n on the typed Tauri API (Monaco and revision-checked YAML/FTL editing are already enabled).
2. Incremental file watcher and persistent SQLite index with rapid warm startup (manual full-rescan refresh is now the safe baseline).
3. Correct lossless YAML/CST editing, unique declaration identity, SS14 inheritance and partial prototype semantics; verification against RobustToolbox fixtures.
4. Conflict-safe file saving with revision checks, atomic replace where supported, useful error explanations and recovery steps.
5. C# metadata analysis, Fluent parsing and diagnostics, RSI metadata/images with lazy binary previews.
6. Search/graph/UI optimization and benchmarks on several real SS14 forks.
7. Signed installers, lockfiles, cross-platform smoke tests, stable release pipeline.

Rules: prevent data loss, do not hide errors or fake success, do not silently overwrite external changes, keep CI green, and measure performance before promising speedups.

The index is a snapshot, so a path reported absent may exist on disk; refreshing the workspace rebuilds the catalog. Unlike Electron’s scanner, RSI directories are indexed even when their metadata is missing or invalid.
