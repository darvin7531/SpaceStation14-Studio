# Rust Rework — план миграции и критерии готовности

**Рабочая ветка:** `rework/rust-tauri` · **цель:** заменить старую Node/Electron-версию редактором на Rust + Tauri 2 без потери возможностей. Это **не v2** и не обещание стабильного релиза.

Этот документ — постоянный план для следующих циклов работы. В каждом цикле:
1. выбираем конкретную незавершённую задачу и определяем проверяемые критерии;
2. меняем код, добавляем регрессионные тесты и документацию;
3. коммитим изменения в `rework/rust-tauri`, проверяем GitHub Actions (frontend, Rust, Clippy, Tauri build);
4. отмечаем выполненное **только после проверки**, сообщаем оставшиеся риски и выбираем следующий пункт.

Обозначения: **[x]** реализовано и проверено; **[~]** сделана часть; **[ ]** ещё не завершено. Пройденный CI не означает, что GUI протестирован вручную. Все проценты — инженерная оценка сопоставления функций, а не автоматический расчёт по числу файлов.

- **База до текущего цикла:** около **40% готовности к функционально полноценной, стабильной замене Electron**.
- **После FTL-редактирования:** ориентировочно **41%** (CI пройден).
- **После создания FTL:** ориентировочно **42%** (код и Linux Tauri compilation прошли CI).
- **После Fluent-диагностики:** ориентировочно **43%** (CI пройден).
- **После индекса ссылок Fluent:** ориентировочно **44%** (CI пройден).
- **После первого этапа C#-индекса:** ориентировочно **45%** (реализован структурный каталог и оптимизация сканирования; CI пройден).

## Неизменяемые правила

Никакого скрытого изменения исходников, потери черновиков, ложного статуса «готово» или автоматического merge без подтверждения. Ошибки объясняют действие пользователю. Функции старой программы сверяются по факту, а не по названию. Каждый значимый цикл завершается коммитом, ссылкой на CI и обновлением этого чек-листа. Ручной пользовательский тест по договорённости проводится только после завершения основных функций; до этого регрессии покрываются автоматическими проверками.
